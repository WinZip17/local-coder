# Карта проекта Local Coder

Десктопное приложение для локальной разработки на любом языке. Electron + React + TypeScript. Интерфейс на русском. Один чат — одна папка проекта и один контекст. Пока в настройках не сохранена рабочая модель, чаты, правки файлов и консоль закрыты.

Полная карта для модели — этот файл. Служебная копия, которую приложение вставляет в системный промпт, лежит в `.local-coder/project-map.json`. При обновлении карты приложение заново сканирует дерево и документы, но сохраняет `summary` и `notes`, если `summaryFromAgent` истинно.

## Нельзя ломать

- Git запрещён целиком. `isGitCommand` в `src/shared/safety.ts` режет любую команду, где отдельный токен — `git` или `git.exe`. Запись в каталог `.git` закрыта `resolveInsideProject`. Коммиты делает только пользователь. Не добавлять git-операции в агента, раннер или IPC.
- Правки файлов применяются сразу (`write_file`, `edit_file`), без подтверждения и без отката через git.
- `run_command` и поиск DuckDuckGo выполняются только после явного ответа пользователя (`agent:decide`). Уточнение `ask_user` ждёт текст (`agent:answer`).
- Все пути инструментов остаются внутри папки чата. Выход наверх и другой диск — ошибка.
- Одна папка — один чат. Ключ папки: `projectKey`, на Windows без учёта регистра. Повторное открытие возвращает тот же чат.
- Модель можно сменить в любой момент. Следующий запрос берёт уже новые настройки. Без валидной модели `modelProblem` не пустой, и работа не начинается.
- Прокси (HTTP, HTTPS, SOCKS5) идёт только на внешние запросы API и поиска. `localhost`, `127.0.0.1` и `::1` идут напрямую. Запуск проекта прокси не наследует.
- Секреты (ключ API, пароль прокси) живут в userData и не попадают в промпт, в карту и в репозиторий проекта.

## Процессы

| Слой | Путь | Роль |
| --- | --- | --- |
| Main | `src/main` | Файлы, модели, агент, процессы, IPC. Единственное место для Node и `node-llama-cpp`. |
| Preload | `src/preload/index.ts` | `contextBridge`, API `window.localCoder`. |
| Renderer | `src/renderer` | React-интерфейс. Без `fs`, без прямых запросов к моделям. |
| Shared | `src/shared` | Типы, настройки, разбор инструментов, запреты. Можно импортировать отовсюду. Чистые функции. |

Renderer говорит с main только через каналы IPC. События наружу: `agent:event`, `runner:event`. Ответы IPC — `Result<T>`: `{ ok: true, data }` или `{ ok: false, error }`.

Сборка: `electron-vite`. Точка входа Electron — `out/main/index.js`. `node-llama-cpp` остаётся external и грузится через `import()`, потому что пакет ESM. `undici` и `fetch-socks` подключаются через `require`.

## Поток одного сообщения

1. `App.tsx` вызывает `sendMessage`. Main пишет сообщение пользователя в чат и шлёт событие `message`.
2. `ensureProjectMap` обновляет дерево и документы, не затирая агентское описание.
3. До 8 шагов (`MAX_STEPS` в `src/main/agent.ts`). На каждом шаге системный промпт собирается заново из карты.
4. В модель уходят system + последние 24 свёрнутых сообщения. Сообщения `tool` для модели выглядят как пользовательские «Результат инструмента».
5. Ответ разбирает `parseModelOutput`: видимый текст и блоки `<tool_call>{json}</tool_call>` либо ограда ` ```tool `.
6. Обычные инструменты выполняются сразу. `ask_user` останавливает остальные вызовы этого ответа. `run_command` и `web_search` ждут подтверждения.
7. Результаты пишутся в чат как `role: tool`. Если вызовов нет, цикл заканчивается. На 9-м шаге модель просят написать «продолжи».
8. Отмена — `AbortController` на чат. Частичный ответ не исполняет инструменты.

## Модели

Активный провайдер — одно из `local`, `ollama`, `openai`.

- Локальная: файл `.gguf`, контекст 512–262144, по умолчанию 8192. GPU: `auto` (CUDA, иначе Vulkan), `cuda`, `vulkan`, `cpu`. Вызов `getLlama({ build: 'never' })`, чтобы приложение не собирало llama.cpp из исходников. `loadModel` получает `gpuLayers.fitContext` с выбранным контекстом: на GPU уходят только слои, которым хватает видеопамяти вместе с KV-кэшем, остальные остаются в оперативной памяти. Если оценка всё же не сходится, загрузка повторяется с меньшим потолком слоёв на GPU. Веса держатся в кэше, контекст создаётся на запрос и освобождается. Одновременные локальные генерации идут очередью. Если проверка CUDA и Vulkan не проходит, llama.cpp сам спускается на CPU; проверка модели говорит об этом прямо и показывает, сколько слоёв на GPU и сколько в оперативной памяти.
- Ollama: `POST {baseUrl}/api/chat`, поток NDJSON. Список: `GET /api/tags`. Адрес по умолчанию `http://127.0.0.1:11434`.
- API: `POST {baseUrl}/v1/chat/completions`, поток SSE. Ключ необязателен для локального совместимого сервера. Пустой ключ допустим.

Температура запросов 0.2. Токены в интерфейс уходят пачками примерно раз в 40 мс.

## Инструменты агента

Имя и аргументы приходят JSON-объектом внутри `<tool_call>`.

- `list_dir` — один уровень, не больше 200 имён. `path` по умолчанию `.`.
- `read_file` — окно строк `offset` (с 1) и `limit` (по умолчанию 400, максимум 800). Ответ обрезается около 12 000 символов.
- `search_in_project` — подстрока от 2 символов, до 40 совпадений и 4000 файлов. Каталоги зависимостей и бинарные расширения пропускаются.
- `write_file` — полная замена, атомарно через временный файл. Потолок около 1,5 млн символов.
- `edit_file` — точная замена `oldText`. Несколько вхождений без `replaceAll: true` — ошибка, чтобы не заменить не тот фрагмент.
- `update_project_map` — описание и заметки. Дерево при этом пересканируется.
- `run_command` — после подтверждения, рабочая папка чата, один процесс на всё приложение. Вывод дублируется в консоль и возвращается модели (хвост около 100 000 символов).
- `web_search` — после подтверждения, POST на `https://html.duckduckgo.com/html/`, до 5 результатов.
- `ask_user` — вопрос пользователю, после него остальные вызовы того же ответа пропускаются.

## Данные

Настройки и чаты: `%APPDATA%/local-coder` (Electron `userData`), файлы `settings.json` и `chats.json`. Запись атомарная. Битый JSON переименовывается в `.broken`.

Карта открытого проекта: `{проект}/.local-coder/project-map.json`. Рядом `.gitignore`, чтобы служебная папка не попадала в коммит пользователя. Сканер идёт на глубину 4, до 500 узлов и 5000 посещений. В дерево попадают каталоги и исходники. Документы: `README.*` и markdown/txt/rst в `docs`, `doc`, `documentation`, `wiki`. До 12 документов, выдержка до 3500 символов, общий бюджет около 20 000. Пропускаются `node_modules`, `.git`, `.local-coder`, `dist`, `build`, `out`, `release` и другие каталоги сборки.

Удаление чата удаляет переписку из userData. Папка проекта и его карта остаются.

## Интерфейс

Состояние окна лежит в Zustand (`useAppStore`): чаты, активный проект, поток ответа, консоль и панели. Форма настроек держит черновик в `useSettingsForm`, пока его не сохранят. Слева список чатов, «Открыть проект» и внизу кнопка «Настройки». Кнопка «Скрыть» увозит этот блок влево слайдом; вернуть его можно кнопкой «Чаты» на краю рабочей области. Та же кнопка «Настройки» есть в шапке открытого чата. Справа переписка, статус шага, карточка подтверждения или уточнения, поле ввода. Снизу консоль: команда, запуск, остановка, stdout / stderr / system. «Скрыть» в шапке консоли увозит её вниз слайдом, «Консоль» на нижнем краю возвращает. На узком окне чаты уезжают вверх. Пока модель не готова, на весь экран экран настроек. Позже настройки открываются поверх работы. Вкладки экрана: «Модель» и «Прокси». Сохранение пишет обе сразу.

Экран настроек не закрывает ворота, пока `modelProblem(draft)` не пустой. «Проверить загрузку» и «Загрузить список моделей» пишут настройки на диск, но не снимают ворота. Ворота снимает «Сохранить».

## Сборка и проверка

- `npm run dev` — electron-vite, окно с горячей перезагрузкой.
- `npm run build` — каталог `out/`.
- `npm run preview` — собранное приложение.
- `npm run dist` — NSIS в `release/` (`electron-builder.yml`, `appId` `dev.localcoder.app`). Нативные файлы `@node-llama-cpp` и `node-llama-cpp` распаковываются из asar.
- `npm run typecheck` — `tsc --noEmit`.
- `npm test` — `src/shared/safety.test.ts`: git, границы папки, ключ проекта, разбор tool_call, ворота без модели.

Окно: `src/main/index.ts`, контекст изолирован, `nodeIntegration` выключен, `sandbox` выключен из-за preload. Чужие ссылки открываются снаружи, навигация окна отменена.

## Что не делать при доработках

- Не переносить `node-llama-cpp` в renderer и не бандлить его в main.
- Не отдавать в renderer сырой `ipcRenderer`.
- Не выполнять инструмент по тексту, который не разобрал `parseModelOutput`.
- Не писать ключ API в логи, карту и сообщения об ошибках целиком, если в тексте ошибки вдруг окажется заголовок Authorization.
- Не запускать вторую команду, пока жива первая: раннер один на приложение.
- Не расширять лимит шагов без причины: длинный цикл сам пишет файлы.
